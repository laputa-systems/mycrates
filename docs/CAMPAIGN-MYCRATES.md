## Charter

## Decisions

Owner decisions: none outstanding. The brief is the owner's intent. Everything below is prescribed or delegated; the owner may overrule any line.

- Prescribed: one crate, `src/lib.rs` + `src/main.rs`, edition 2024, `rust-version` = installed stable (1.99). Apache-2.0 `LICENSE` copied from `../mypypi`. Unix only (macOS, Linux). Reverse: owner order.
- Prescribed: the model is mynpm's. `import-lock` and `add` only record exact pins (offline). `fetch` acquires and verifies. `publish` renders generations from verified local state and never touches the network. This supersedes the brief's wording that `import-lock` itself downloads; the README quickstart runs `import-lock` then `fetch`.
- Prescribed dependencies, all sync, no Tokio, no OpenSSL: `serde`, `serde_json`, `toml`, `semver`, `sha2`, `flate2` (miniz_oxide backend), `tar`, `lexopt`, `httparse`, `ureq` 3 (`rustls`, `gzip` off; ring + webpki-roots). Measured: 66 crates in the tree, cold release build 7.95 s wall / 39 s user with an empty `main` (kache bypassed). Dev-only: `tempfile`. No others without a stated reason in the commit body. Locking uses std `File::try_lock` (verified stable on 1.99), so no `libc`, `fs2`, or `unsafe`.
- Prescribed: CLI parsing is lexopt-only with one declarative command schema that generates help (`rust-cli-lexopt` conventions), so `-h` output is the README's CLI reference.
- Prescribed: the write service is hand-rolled over `std::net` + `httparse`: thread per connection capped at `limits.concurrent_requests`, read and write timeouts, `Content-Length` bodies only (chunked gets 411), streamed to a temp file under the state dir, never buffered whole. It binds loopback by default and serves only `/api/v1/crates/*`. A reverse proxy strips any path prefix and terminates TLS. Reverse: swap in `tiny_http` if the hand-rolled server needs more than ~300 lines.
- Prescribed: auth is one token. `serve-publish` reads it from `--token-file` (must be mode `0600`, else refuse to start) or `MYCRATES_TOKEN`; it compares SHA-256 digests in constant time, and it never logs the token or `Authorization`. Config files never contain it. `config.json` sets `auth-required: false`; reads are public.
- Prescribed: layout. State dir (`--state-dir`, default `.work/state`): `blobs/<sha256>.crate`, `native/<lowername>/<version>.toml` (accepted publish record, indexed fields, `yanked`), `upstream/<lowername>/<version>.json` (upstream index line, verbatim bytes, plus checksum and acquisition record), `pins/<project>.toml` (import-lock result: exact registry pins, unsupported sources, manifest snapshot), `lock` (flock target). Site dir: `blobs/<sha256>.crate` (hard link from state, copy on `EXDEV`, hash-verified, never removed), `generations/<id>/{registry,crates-io}/...`, `current` symlink (replaced by `rename` of a temp symlink). Generation id = first 24 hex of SHA-256 over canonical sorted `(view, path, sha256)` records plus the renderer version. Full tree per generation; older generations kept for rollback. Records are TOML or JSON written deterministically.
- Prescribed: `config.json` for the native view is `{"dl": "<base>/blobs/{sha256-checksum}.crate", "api": "<base-origin-and-prefix>", "auth-required": false}`; the mirror view omits `api` so `cargo publish` to it fails loudly. `<base>` comes from config `public_base_url`, which may be an origin root or carry a path prefix. Index files are `<view>/<shard>/<lowercase name>`: `1/n`, `2/n`, `3/<c>/n`, else `<2>/<2>/n`.
- Prescribed: native identity. A crate name must match Cargo's charset (ASCII alphanumeric, `-`, `_`, starts with a letter, at most 64). The uniqueness key is lowercase with `-` equal to `_`: publishing `Foo_Bar` after `foo-bar` is rejected naming the existing crate. A version's key is its semver without build metadata: `1.0.0+b` after `1.0.0+a` is rejected. Same key and same bytes is a successful no-op. Same key and different bytes is a conflict. Native and upstream names are independent namespaces.
- Prescribed: the publish-to-index transform follows the observed wire behavior (pinned by a real probe, 2026-10-29): `deps[].version_req` becomes `req`; a renamed dependency has `explicit_name_in_toml` in the publish body, becomes `name` = alias in the index, and `package` = the real crate name; a dependency on the same registry has no `registry` key and becomes `"registry": null`; a crates.io dependency arrives as `"registry": "https://github.com/rust-lang/crates.io-index"` and is kept verbatim; any other registry URL is kept verbatim. Features containing `dep:` or `?` go to `features2` with `"v": 2`; otherwise `v` is 1. `links` and `rust_version` are carried. Yank state is the only mutable bit of a native record.
- Prescribed: upstream index lines are stored and re-emitted verbatim, so unknown fields (the live index already carries `pubtime`) survive. The mirror line for a version is the line fetched, with `yanked` as of acquisition; a later upstream yank is not followed. Mirror index files contain only the versions archived. Never state or imply the mirror holds every semver resolution.
- Prescribed: verification trust chain for upstream. The expected checksum is the lock `checksum`, which must equal the upstream index `cksum`, which must equal the SHA-256 of the streamed download. Any mismatch deletes the temp file and leaves no record. Absent lock checksum for a registry package is an error, never a skip.
- Prescribed: archive policy. Native uploads and upstream downloads get the same structural scan, streamed, with no extraction to disk: gzip and tar must parse; every path is relative, has no `..`, and lies under `<name>-<version>/`; no hard links or symlinks with absolute or escaping targets; `<name>-<version>/Cargo.toml` must exist and its `package.name` and `package.version` must equal the declared ones; entry count, per-file size, total expanded size, and expansion ratio are bounded by `[limits]`. Defaults: 1 GiB compressed, 4 GiB expanded, 200,000 entries, ratio 1000. Config overrides them; no value is a protocol constant. Delegated: if a legitimate crates.io crate trips the symlink rule in the public smoke, relax only that rule, naming the crate in the commit body.
- Prescribed: network policy. Redirects at most 5, request timeout 5 min, fetch timeout 1 h, 4 concurrent downloads, `limits.fetch_bytes` 10 GiB per `fetch`, HTTPS-only to upstream unless the configured upstream is loopback (tests). Upstream URLs are config (`upstream.index_url`, default `https://index.crates.io/`), so tests need no real network. The dl template supports `{crate}`, `{version}`, `{prefix}`, `{lowerprefix}`, `{sha256-checksum}` and defaults to appending `/{crate}/{crate}-{version}.crate`; any other marker is an error.
- Prescribed: crash testing uses on-disk states a crash leaves (partial staging, temp symlink, temp blob, stale lock file) plus a SIGKILL loop against the real binary. No test-only seams or failpoints in production code.
- Prescribed: error model. One `Error` enum with categories `input`, `integrity`, `conflict`, `limit`, `network`, `operation`, mapped to distinct nonzero exit codes. The service maps them to Cargo's `{"errors":[{"detail":"..."}]}` body. Delegated: HTTP status per category. For each, the executor checks with real `cargo publish` and `cargo yank` that the detail text reaches Cargo's stderr, and keeps statuses that do.
- Prescribed: egress claims. Tests use `CARGO_HTTP_PROXY=http://127.0.0.1:1` with `NO_PROXY=127.0.0.1`: probe-confirmed that this fails any non-loopback Cargo request. That is "proxy-denied", and the docs call it that. Only the Linux `docker run --network none` run (H3) may be called network-denied.
- Prescribed: builds. Fetch-only tests (`cargo metadata --locked`, `cargo fetch --locked`) live in files separate from build tests. Build tests compile only locally authored fixture crates, never third-party code. The public smoke (real crates.io) is `#[ignore]` and never builds.
- Prescribed: README examples are executed. Fenced blocks tagged `sh verified` are extracted and run in order by `tests/readme.rs` against a loopback fixture, with the placeholder `https://deps.example.net/mycrates/` substituted by string replacement. Reverse: if this exceeds ~100 lines, fall back to a README quickstart test written by hand plus a drift note in AGENTS.md.
- Prescribed: CI is in scope because the brief asks (the one exception to "CI only when asked"). One workflow `ci.yml`, `permissions: contents: read`, `ubuntu-24.04` and `macos-26`, `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` with `persist-credentials: false` (the pin the sibling repos use), no other third-party actions, stable Rust from the runner's rustup. Steps: `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`, plus an Ubuntu job running the test suite in `docker run --network none`. The executor writes it but never runs formatters or pushes.
- Delegated: `generation id` length, error text, module split inside the named files, fixture contents, and the cap values above, each with the smallest reversible choice; log in the commit body only when a later slice depends on it.

## Execution boundary and non-goals

Authorized: git init, branches, worktrees under `.work/wt/`, and commits on `main` in this repo; reading `../mynpm` and `../mypypi`; `cargo` builds and tests with kache; loopback listeners on ephemeral ports; reads from `index.crates.io` and `static.crates.io`; `docker pull` of the pinned Rust image and `docker run --network none` (H3); `gh` read-only.

Forbidden: pushing, `gh repo create`, and any other `gh` write; editing `../mynpm`, `../mypypi`, or any file outside this repo; writing to the user's real `~/.cargo`; running third-party build scripts or proc-macros; installing system packages; formatters; touching `plan.md`.

Contract changes for the owner. All are new, so nothing breaks: the config schema (`version = 1`), the state and site layouts above, the token mechanism, the CLI surface, the index and wire transform rules, and the three supersessions: `import-lock` records pins and `fetch` downloads; the brief's `../laputa` example is replaced by fixtures; CI uses no third-party Rust toolchain action.

Non-goals, from the brief: web UI, search, accounts, OAuth, organizations, owner APIs, statistics, advisories, auto-publish to crates.io, mirroring the whole catalog, containers, databases, a Git index, and a legacy index protocol. Also out of scope: Windows, `auth-required` registries, and object-storage adapters (the layout keeps `current` outside the blob store so one can follow).
